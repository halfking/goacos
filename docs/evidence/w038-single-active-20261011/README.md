No new tables/migrations, request forwarding, second registry, production writes or automatic HA acceptance. Exact baseline/auth integration/runtime/resource identities are in `baseline.json`; final commands, environments, exits and timing are in `verification.json`.

## Contract and implementation

`Store.AcquireConfigOwnership` reserves one physical `database/sql.Conn`, obtains one PostgreSQL session advisory lock or MySQL named lock derived from the actual selected database, and rejects a competing instance. A positive pool capacity of one is refused because fresh auth/registry checks need pool capacity apart from the reserved session. MySQL activation requires all four canonical config/history/tag/namespace tables to be InnoDB. Existing nontransactional rows/tables are preserved and rejected without conversion.

`WithConfigTransaction` serializes short operations on this actual locked connection, checks ownership on that connection before work and within the transaction before commit, and binds nested Store calls using an unexported context key. Every actual source consumer of `config_info`, history and tags is routed through this facade, including namespace config counts/deletion preconditions and metrics. Raw pooled auth/naming/bootstrap operations keep their existing authority. No process label or cached boolean authorizes SQL. The physical session is discarded on loss/release, rather than returned to the pool with a live advisory lock. A lost Store cannot reacquire; a fresh process/Store must compete and preload committed state.

Mounted v1/v2 config routes buffer HTTP output (16MiB cap), run config+history+tags in a single owned transaction, rollback rejected/failed handlers, and flush success/local notification only after commit. A lost session cannot replay the statement through another pool connection. Unknown commit outcome remains possible when an acknowledgement is lost: the operation may have committed **before** takeover, and callers receive failure; this slice does not add client idempotency tokens. Transaction atomicity preserves config/history in either outcome.

The Hub's preload/local MD5 map is a notification optimization, never current-value authority. Long listeners park outside the semaphore/connection, compare current MD5 through short owned transactions, use local notifications or a one-second tick, and do a final fenced check before emitting their buffered result. Read/response linearization is that final owned transaction; this does not promise bytes already transmitted can be revoked after a later failure. If ownership is lost while waiting, the listener returns 503, including empty/invalid-payload paths via final admission.

## Source-backed database rationale

PostgreSQL [session advisory locks](https://www.postgresql.org/docs/17/explicit-locking.html#ADVISORY-LOCKS) release at session end and are database-local; [pg_locks](https://www.postgresql.org/docs/17/view-pg-locks.html) exposes the bigint key as high/low halves with `objsubid=1`. MySQL [GET_LOCK / IS_USED_LOCK](https://dev.mysql.com/doc/refman/8.4/en/locking-functions.html) binds ownership to a connection, independently of transaction commit. MySQL [transaction documentation](https://dev.mysql.com/doc/refman/8.4/en/commit.html) explains that changes to nontransactional tables cannot be rolled back. The implementation's inference is to couple all config transactions to the owning session and reject legacy non-InnoDB tables. These facts support the design; the actual fixtures supply the acceptance evidence.

## Replay, audit and rollback

Run `python3 docs/evidence/w038-single-active-20261011/run_verification.py` with the owned private fixture files intact, then `normalize_coverage.py`. It parses synthetic DSNs only in process memory and does not discover/read production configuration. Required tool paths, exclusive Go cache and target overrides are recorded. The parent/reviewer must serialize fixture use; MySQL failure injection briefly converts only the owned history table and restores its exact index and engine before exit.

The source and both actual host/Linux-arm64 binaries are scanned. JSON exit0 alone never means clean: each report counts OSV metadata separately from finding records and reachable trace functions. `go.mod`/`go.sum` are unchanged; builds use recorded Go1.27.2. The module's `go 1.27` line by itself does not guarantee patched runtimes for future external builds.

Rollback is a local Git revert of this slice on top of accepted auth `418b4df` (no schema migration/data conversion). Reverting removes the serving fence and restores the demonstrated stale-listener limitation, so no multiple-instance/HA deployment should be claimed. Disposable fixture containers can be removed by their exact recorded IDs after independent replay. No production deploy, shared private-state mutation, credential rotation, DNS change, paid service or push occurred in this task.

Open: cross-replica HA/automatic routing/failover, different DB-primary authority or split-database scenarios, production/network-partition performance, namespace/service ACLs and atomic auth revocation (accepted auth only checks fresh request admission), deployment runtime pinning, global platform integration and ledger gates. DB-admin raw SQL/schema changes are privileged maintenance outside HTTP serving authority; this fence does not prevent a database administrator deliberately bypassing the application. A partition leaving the old DB session alive blocks takeover until that session ends, preserving safety while reducing availability.
