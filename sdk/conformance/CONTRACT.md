# goacos 注册 SDK：三语言契约

Go / Python / Node 三套绑定实现同一份线上契约。本文件是那份契约；`run.py`
是把它钉住的检查。

```bash
python3 sdk/conformance/run.py     # 退出码 0 = 三者一致
```

---

## 为什么需要这一层

三套实现各自带测试时，漂移不会表现为崩溃，而表现为：

- 心跳丢了查询串里的 `ip` → 服务端按 `(serviceName, ip, port, clusterName)`
  定位实例，于是心跳打到**另一个实例**上，返回 200，而真实实例在 15s 后
  不健康、30s 后被淘汰。看起来注册中心一切正常。
- 退避上限被调到 60s → 超过 goacos 的 30s 淘汰窗口，实例在被重新注册之前
  就已经被删掉，**永远不会回来**。
- 某一套不采纳服务端下发的 `clientBeatInterval` → 淘汰策略由客户端说了算，
  与服务端脱钩。

这三种漂移在各自 SDK 的单元测试里全部是绿的。只有把三套放在一起跑同一
个场景、逐字比较上线报文，才能发现。

## 六条不变量

三套实现都必须满足，且都有测试钉住：

1. **注册失败绝不影响宿主应用。** 注册中心宕机、配置错误或尚未部署，都不
   能让服务停止对外服务。三套都是记录日志并退避重试。
2. **绝不猜测通告地址。** 未配置 `ip` 时 `register()` 抛错，而不是嗅探网
   卡。在 netbird + 局域网 + docker 网桥的多网卡主机上，嗅探出来的地址几
   乎必然是调用方到不了的——「已注册但流量永远不到」比启动时大声失败难查
   得多。
3. **心跳节奏由服务端说了算。** 采纳 `clientBeatInterval`，因为淘汰策略也是
   服务端的（15s 不健康 / 30s 移除）。
4. **退避不得超过淘汰窗口。** 上限 30s。退避一旦超过，实例在下次尝试之前
   就已被删除。
5. **连续 3 次心跳失败即重注册。** 服务端可能已经把实例淘汰，继续心跳没有
   意义。
6. **2xx 里的非零 `code` 是错误。** goacos 在部分路径上用 HTTP 200 加
   `{"code":400,...}` 拒绝注册；把它当成功，就是「注册成功但实例从未出现」。
7. **「未设置」只有一个意思，且必须归一。** 空串与纯空白都算未设置，group /
   cluster 要取默认值。`"   "` 不是空的名字，是**另一个不可达的名字**：实例
   落进没人查询的分桶，而每一层都报成功。compose 与 `.env` 里带游离空格是常事，
   于是同一份配置下 Go/Node 的服务落进 `DEFAULT_GROUP`、Python 的服务落进
   `group="   "`，网关同步脚本按 `DEFAULT_GROUP` 取实例时看不到后者。

### 已知差异：`namespace_id` 不做空白归一（刻意）

Go 原样透传、Python 原样透传、**Node 会 trim**。本契约不判它红，因为
namespace 不参与「数据面按默认名取实例」那条路径，后果远轻于第 7 条。记在此处
是为了让「为什么只有 group/cluster 归一」有答案，而不是留给下一个读代码的人
去猜是不是漏了。要收紧的话，三边要一起改，并给 `run.py` 第 [5] 节补上
namespace 的用例。

## 第 [5] 节补记：判据自己的盲点（2026-10-14）

原先的四节**看不见**第 7 条：三个绑定传的 group/cluster 本来就等于默认值，
于是无论各自怎么归一，上线报文都长得一样——**分歧在那个场景里天然不可见**。

把 Go 的 `strings.TrimSpace(v) == ""` 退回 `v == ""`，四节全部照常通过，
套件报的是「三语言契约一致」。实测确认后才补上第 [5] 节，它用「空串」和
「纯空白」两组输入各跑一次真实注册，比对**真正上线的** group/cluster。

Go 那一侧是**静态读源码**（`orString` 的判空条件是否带 `TrimSpace`），不是
运行验证——套件的设计前提是没有 Go 工具链也能跑。能力边界写在该函数的
docstring 里，不含糊过去。

补上之后第一次跑就报红：Python 原样发空串与三个空格。修复后变异验证：
退回 Python 归一 → 第 [5] 节红 2 条且 Python 自测红 4 条；
退回 Go 的 TrimSpace → 第 [5] 节报出 Go 那一条。

**另一个同源的坑**：第 [5] 节在失败时最初仍会打印一行 ✅。一条与失败并排出现的
✅ 比没有更糟——它让整屏输出在有问题时依然看起来是绿的。现在只在没有新增失败
时才报成功。这与上面「幻影漂移」是同一个教训。

## 单元测试与跨语言检查的分工

| | 单元测试 | `conformance/run.py` |
|---|---|---|
| 跑什么 | 每个绑定对着脚本化的假注册中心 | 三套跑同一场景，比对上线报文 |
| 能抓 | 单语言内的行为回归 | **跨语言漂移** |
| 抓不到 | 别的语言悄悄改了什么 | 绑定内部的重试/退避逻辑细节 |

两者都做变异测试验证过（各自 13 项与 9 项变异全部被捕获）。

## 两个由验证过程本身暴露的坑

记录在此，因为它们都会让检查「看起来通过」而实际失效。

### 1. 陈旧 `.pyc` 会掩盖契约违规

CPython 用**整秒 mtime + 字节长度**判定 `.pyc` 是否有效。把
`/v2/ns/instance/beat` 改成 `/v1/...` **长度不变**，若变异发生在上次导入
的同一秒内，解释器会直接加载旧字节码 —— 契约检查报告「一致」，而绑定已
经漂移。这个坑是被变异测试发现的：第一次跑该变异时它存活了，手工复现却
能抓到，差别只在于手工那次清了 `__pycache__`。

修法：`run.py` 顶部 `sys.dont_write_bytecode = True`，子进程用 `-B`。

**任何验证源码改动的脚本都必须先解决这件事**，否则它验证的是磁盘上的旧
字节码，不是你刚改的源文件。

### 2. 空值解析差异会造出幻影漂移

`urllib.parse.parse_qsl()` 默认丢弃空值（`namespaceId=` 直接消失），而 Node
的 `URLSearchParams` 保留它。用 Python 默认参数观测，会每次都报告「Node
多发了一个参数」——而两边其实都发了。必须 `keep_blank_values=True`。

这类幻影比漏报更危险：它训练所有人忽略这个检查。**宁可让检查在某次真实
漂移时多报一次，也不要它每次都误报。**

## 新增一种语言绑定时

1. 实现上面六条不变量；
2. 把常量按同名加进去，并让 `run.py` 的 `*_contract()` 能读到；
3. 在 `run.py` 里加一个 `wire()` 场景，返回归一化后的请求列表；
4. **对自己的绑定做变异测试**，确认判据真能判出自己的错。

不要为了省事跳过第 4 步——本文档里 13 个变异中的 3 个，正是靠它才发现
判据本身的缺陷。
